# Security Policy

## Supported Versions

As of November 2nd, 2026, I will provide security updates and patches for only the latest version of **Aurelia**. The current release is [v3.0.1](https://github.com/LeTrollologist/Aurelia/releases/tag/v3.0.1).

---

## VirusTotal Verification (API v3)

Every release's two binaries — the portable zip and the Inno Setup installer — are
submitted to VirusTotal during the pipeline's `virustotal` stage, and the release aborts
if any engine reports a detection:

- **Endpoint/contract**: `POST /files` (multipart, ≤ 32 MB) or `POST /files/{sha256}/analyse`
  for samples VirusTotal already holds, then `GET /analyses/{id}` until `status == completed`
  with engines actually reporting.
- **Credential**: read from the `VIRUSTOTAL_API_KEY` environment variable only — never from a
  file, never committed.
- **Quota discipline**: the public API allows 4 requests/minute and 500/day, so the client
  paces every call 15 s apart and retries documented `429`/`503`/`504` responses.
- **Published evidence**: `virustotal-summary.txt` (per-artifact verdicts and permalinks,
  hashed in `SHA256SUMS.txt`) and a verdict table inside the release notes.

The scanner lives in `scripts/virustotal.py`; see `RELEASE_PROCESS.md` §7 for the full
contract.

## Release Integrity (SHA-256 + local release records)

Since **v2.1.0** releases ship a portable zip and an Inno Setup installer instead of
signed `.vpack` packages. Integrity is established by the local release pipeline rather
than a signature:

- **`SHA256SUMS.txt`** is generated during the pipeline's `verify` stage, and the upload
  stage (`ship`) refuses to publish any artifact whose bytes do not match it.
- **`releases/<tag>.json`** records every published asset with its size and SHA-256, the
  test summary and a republish counter, so a rebuild can prove byte equality.
- **PE sanity checks**: the installer is verified to be a real Windows executable above a
  size floor before it is hashed and shipped.

> Ed25519 publisher signing (previously used for `.vpack`) is retired for now; the key
> material remains in `keys/` so signing can return without a new identity.

## Automated Dependency Security Audit (`cargo audit`)

Every release build should be scanned through `cargo audit` before packaging to verify that zero dependencies contain known security advisories or vulnerabilities tracked by the [RustSec Advisory Database](https://rustsec.org/):

1. **Pre-Release Security Gate**: run `cargo audit` before `make release`; the pipeline
   aborts on a failing build or test suite, and the audit is a manual gate today.
2. **Reproducible Local Verification**: you can run the dependency audit locally at any time:
   ```powershell
   cargo audit
   ```

## Binary Integrity Verification

Every official release distribution package (`Aurelia-v<version>-win64.zip` and
`Aurelia-Setup-<version>.exe`) is hashed locally before publication:

1. **Cryptographic SHA-256 Checksums**: every release artifact appears in `SHA256SUMS.txt`
   with its digest, generated by the pipeline's `verify` stage.
2. **Upload gating**: `scripts/release_page.py` recomputes each hash immediately before
   uploading and aborts if a file disagrees with the manifest.
3. **Independent Verification**: users can check a download against the manifest, or submit
   the archive to [VirusTotal](https://www.virustotal.com/gui/home/upload) themselves.

### How to Verify a Downloaded Release
```powershell
# 1. Compute SHA-256 on Windows
certutil -hashfile Aurelia-Setup-3.0.1.exe SHA256

# 2. Compare with the matching line in SHA256SUMS.txt
Get-Content SHA256SUMS.txt

# 3. Optional: check the hash against VirusTotal in your browser
# https://www.virustotal.com/gui/file/<SHA256_HASH>
```

## Reporting a Vulnerability

The Aurelia team takes the security of our application and our users seriously. If you believe you have discovered a security vulnerability in Aurelia, please follow these steps:

1. **Do NOT disclose publicly**: Please do not file public GitHub issues or discuss potential vulnerabilities in public forums.
2. **Contact Privately**: Send an email directly to the maintainer at `trollologistog@gmail.com` with the subject line `[SECURITY] Aurelia Vulnerability Report`.
3. **Include Details**:
   - A detailed description of the vulnerability.
   - Steps or proof-of-concept to reproduce the issue.
   - The version of Aurelia and your OS environment.
   - Potential impact of the issue.

### Response Timeline
- **Acknowledgement**: You will receive an initial response within 48 hours.
- **Assessment**: We will verify the vulnerability and evaluate its severity.
- **Fix & Disclosure**: We will work on a patch and coordinate a disclosure timeline once a fix is released.

## Security Invariants & Design Principles

Aurelia is engineered with strict local security principles:

- **Memory Safety**: Aurelia is implemented in 100% Rust, taking full advantage of Rust's compile-time memory safety, thread safety, and boundary checks to prevent buffer overflows and memory corruption.
- **Offline First**: Aurelia does not make outbound network connections, run background telemetry, or transmit user artwork.
- **Deterministic File Parsing**: Project archives (`.aur`) and imported image files are parsed using memory-safe decoders with strict bounds validation to prevent arbitrary execution or corrupted heap allocations.
- **Reproducible Local Pipeline**: Release builds are produced locally using the deterministic pipeline in `scripts/pipeline.py` without third-party CI/CD runner vulnerabilities.

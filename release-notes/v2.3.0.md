# Aurelia v2.3.0

The studio chrome gets its overdue redesign: one type scale, panels that never clip
their own controls, and a palette you can actually aim at.

## What changed

### A design system instead of ad-hoc numbers

`aurelia-ui::design` now owns the surfaces, text colours, spacing and the two common
row shapes (`caption + control`, `caption + slider + number`). `style.rs` builds the
egui style from those tokens: one type ladder (11 → 15 px instead of 8.5 → 10), 8×6
item spacing, 26 px hit targets, 96 px sliders and 8 px window rounding. Panel code
asks for `design::section(ui, "COLORS")` instead of hand-rolling another 9.5 px label.

### Panels that fit their controls

Both side panels were fixed-width (220 / 240 px) and clamped their content to 204 / 224 px,
so sliders and combos were simply cut off — `Harden…`, `Spacir…`, `Swap (X)` and the
layer blend selector all bled past the edge. They are now resizable (250–340 / 300–420,
defaulting to 268 / 324) and compute one stable content width that rows may not exceed.

### Tools you can scan

The 23-tool grid is grouped into **PAINT**, **SHAPES & TYPE**, **SELECT** and **NAVIGATE**,
with equal-width buttons, 28 px rows, icons centred against their labels and the active
tool lit in the accent colour.

### A palette worth using

- Primary/secondary colour slots are now 36 px chips with an accent ring on the active slot.
- The hex value of the slot you are editing is printed next to it, with a `⇄ Swap` button.
- Swatches moved from a ragged `horizontal_wrapped` (14 px squares) to a fixed 10-column
  grid of 22 px squares with a hover ring and hex tooltips.

### Header and status bar

- Six cryptic glyph buttons (👁 📐 ⇲ 🎨 🖼 📏) collapsed into a single **View** menu holding
  the same toggles with readable names and shortcuts; **Help** and **About** are labelled.
- The status bar keeps to one line — a stray multi-line status could grow the bar — and
  now shows a save-state dot (teal = saved, amber = unsaved), the document name, zoom and
  cursor/canvas metrics in a monospace strip.

### Layer rows

Layer frames inherited their parent's horizontal layout, which is why the blend mode and
opacity controls rendered *beside* the layer name and got clipped. The frame contents are
now explicitly vertical: name row (with duplicate/delete), then blend mode, then opacity.

## Tooling

`scripts/capture_ui.ps1` renders the running app to a PNG via `DwmGetWindowAttribute`
extended frame bounds, so the chrome can be reviewed and diffed without a human at the
keyboard. It is a development aid only; it is not shipped.

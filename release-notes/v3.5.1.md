# Aurelia v3.5.1 - viewport and file-trust hardening

This is a stabilization release. It adds no editing features; it hardens the viewport, the
project-file parser, and the release process.

## Fixed

- **Empty 16-bit documents now have a rendered-paper regression test.** A blank viewport cannot
  regress for a supported document format without failing the suite.
- **Oversized project claims are bounded before allocation.** Text content remains capped at
  8 MiB; the optional `AED1` editor section and preview length are covered by rejection tests.
- **Release notes are a preflight requirement.** A full release cannot start without
  `release-notes/<tag>.md`.
- **VirusTotal results are written into the notes by the pipeline**, between the standard
  `virustotal:begin` / `virustotal:end` markers, before the tag is created.

## Release process

- The release notes stage replaces the VirusTotal block with the actual artifacts, detection
  counts, engine counts, report links and SHA-256 values.
- Packaging uses the executable produced by the build stage.
- `SECURITY.md` is part of the version set.

## Compatibility

- AUR v1/v2 load read-only; saves continue to write v3.
- 8-bit and 16-bit editing behavior is unchanged.
- The accepted bilinear transparent-edge limitation is unchanged and remains pinned by a test.
- The viewport remains an 8-bit presentation of 16-bit documents.

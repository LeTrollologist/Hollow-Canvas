# Aurelia v2.5.0

Masks, tilt, and a measured baseline — plus honest docs for everything still ahead.

## Layer masks (new)

Layers can now carry an **8-bit raster mask** that scales their alpha at composite
time without touching a single pixel of the artwork:

- **Create from selection** — a mask is cut from the current selection (a fully
  visible mask when nothing is selected), so "hide this layer inside that shape"
  is a two-click operation.
- **Invert**, **enable/disable** and **remove** from the layer card; a disabled mask
  is kept, not thrown away.
- Masks are **non-destructive and copy with the layer** — duplicating a layer
  duplicates its mask.
- Rows show a `◐` badge (dimmed when the mask is disabled).

`LayerMask { width, height, pixels, enabled }` lives in `aurelia-core`, the
compositor folds it into both the fast and the general paths (normal, offset,
blended and adjustment layers), and the project format moved to **AUR v2** with a
per-layer mask section. AUR v1 files still load: they simply have no masks.

Cost, measured on this machine: a masked 4-layer 1920×1080 composite runs at
**92.6 MPix/s** against **113.1 MPix/s** unmasked — about 22 % for the guarantee
that masks never alter pixels.

Not in this release: painting *into* a mask with the brush. Masks are currently
derived from selections; the paint path for masks is the next follow-up (see
ROADMAP).

## Stylus tilt dynamics (new)

`pen_tilt` was sampled from `WM_POINTER` since 2.0 and never used. Freehand strokes
now fold tilt into their width: a pen laid flatter spreads its tip, so the stroke
widens up to `1 + gain` at a 90° tilt. It is **off by default** (`Tilt widens = 0`),
applies only to freehand tools — shapes and gradients keep their exact geometry —
and never changes your stored brush size.

`tilt_size_scale(tilt_x, tilt_y, gain)` is a pure core function with tests for
symmetry across axes, the 0-gain no-op, the 90° ceiling and NaN input.

## Performance baseline (new)

`cargo run --release -p aurelia-render --example bench_composite` measures composite
throughput with no extra dependencies. Recorded for this release:

| Shape of work | Throughput | Per 1920×1080 composite |
| :--- | ---: | ---: |
| Plain 4-layer stack | 113.1 MPix/s | 18.3 ms |
| With a layer mask | 92.6 MPix/s | 22.4 ms |
| Offset + general blend path | 25.7 MPix/s | 80.7 ms |

Documented floors are 40 / 30 MPix/s for the first two. The third number is the
honest weak spot: the general path is ~4× slower than the fast path and is the
first candidate for optimisation work.

## Documentation reconciled

Every document now describes 2.5.0: README highlights (masks, tilt, benchmark),
ROADMAP status and designs, and the release notes. Two items on the requested
list — **colour management** and **multi-document** — are written up as designs
rather than half-built features; see ROADMAP for the concrete plans.

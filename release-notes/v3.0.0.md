# Aurelia v3.0.0

A foundation release. The interesting work is under the surface, and one change is
**breaking in a way you should read before using it on real artwork.**

## Read this first

> **Files saved by this build cannot be opened by Aurelia 2.7.0 or earlier.**
>
> The project format moved to **AUR v3**, which adds per-layer storage-format tags. The new
> reader still opens every v1 and v2 file — that direction is tested — but the old reader
> refuses v3 files, as it must: it has no way to interpret a 16-bit layer.
>
> If you need files that 2.7.0 can open, stay on 2.7.0 for now.

## The honest headline

**This is not a "16-bit release".** There is no way to create or open a 16-bit document in the
interface yet — no menu item, no setting, no import path. What exists is the *machinery*: the
storage format, the compositor, the history, the file format and the whole painting and
transform pipeline now work at either width. Nothing in the UI reaches it.

What that means in practice: this release should behave exactly like 2.7.0 for everything you can
currently do, while writing files 2.7.0 cannot read.

## What is in it

**History rewritten as deltas.** Undo steps now store only the regions an edit changed, in
bytes, with both states, so history is format-agnostic and exact. Measured on 256×256 with
200 strokes: **0.18 MB retained against 100.00 MB — 546× less.** More usefully, a stroke's
snapshot used to cost 16.6 MB at 1080p, which capped undo depth at roughly 30 steps under the
512 MiB budget; a delta step is under a kilobyte, so the budget no longer bounds undo depth.

**Pixel storage behind a type.** `Layer` now holds a `LayerBuffer` with `Srgb8` and `Srgb16`
variants. Accessors are explicit: `as_srgb8()` returns an `Option`, and `as_srgb8_exact()`
returns a view or panics — it never converts and never allocates. The invariant behind the
panic is stated once, centrally, and every call site carries the greppable name, so the day a
16-bit document becomes reachable they all show up in one search.

**The compositor blends 16-bit layers from their own channels.** An early version of this
downconverted to 8-bit before blending, which discarded exactly the precision the format
exists for; it was removed rather than kept as a fast path. Two 16-bit values half a step
apart now stay distinct through a blend.

**AUR v3.** A document-level format tag plus a per-layer tag (`0` inherits). Mixed-format
documents round-trip through the file even though the editor cannot create them. Malformed
input is rejected rather than reinterpreted: unknown document tags, unsupported layer tags,
truncated 16-bit payloads, and impossible dimensions all error — the last of those after a bug
where the guard itself overflowed on `u32::MAX` and panicked.

**Painting and shape filling work at both widths.** Brush strokes, erasing, rectangle, ellipse,
polygon, gradient and flood fill all write native channels. Two of them were already fine and
were tested anyway rather than assumed covered. Flood fill keeps its tolerance comparison in
8-bit terms on purpose — region boundaries are then exactly what they were — while writing
native values. Text is the exception: it composites glyph coverage through its own maths and
has no golden baseline, so it **reports unsupported on a 16-bit layer and touches nothing**
instead of panicking or silently quantising.

**Transforms.** Layer resize, canvas scaling (nearest and bilinear) and all four warped-patch
renderers are width-generic. The canvas-scale kernel was converted with four captured byte
digests proving the 8-bit output did not move.

## Two bounds, stated rather than hidden

- A 16-bit composite downconverted to 8-bit can differ from an 8-bit composite by **1 LSB**.
  The reason is arithmetic, not sloppiness: the 16-bit path divides by 65535 where the 8-bit
  path divides by 255, and `floor(257x/255) ≠ 257·floor(x/255)`. It is measured and asserted
  as a bound.
- The same applies to warped-patch rendering: **1 LSB of 255**, measured.

## Verification

**111 tests pass**, including the unchanged 702-combination compositor oracle, the frozen
alpha-clamp golden baseline, AUR v1/v2 loading, mixed-format and 16-bit round-trips, and the
malformed-file rejections.

Benchmarks, medians of interleaved rounds: general compositing 91.3 MPix/s at 2.7.0's change
and unchanged here; brush painting 192.1 ms for a 240-dab session on 8-bit and 191.7 ms on
16-bit storage — the width costs nothing where the loop is compute-bound.

## Known

The installer is still not Authenticode-signed; a few engines flag it, which is disclosed in
the VirusTotal summary and why the pipeline runs with `--max-detections 4`.

# Aurelia v2.6.1

An internal refactor. **No visual, behavioural or performance change is claimed or
intended** — if a pixel moved or a number moved, that is a bug, not a feature.

## What changed

`Layer::pixels` is no longer public. Callers reach the buffer through four accessors that
say what they mean:

| Accessor | Purpose |
| :--- | :--- |
| `as_srgb8() -> &[u8]` | read-only access |
| `as_srgb8_mut() -> &mut [u8]` | write channels in place |
| `pixels_vec_mut() -> &mut Vec<u8>` | structural changes only (`resize`, `truncate`, …) |
| `set_pixels(Vec<u8>)` | replace the whole buffer |

`LayerMask::pixels` is unchanged: masks are 8-bit by design and were deliberately out of
scope.

**170 call sites across 12 files** (core, io, ui, app, render) were migrated. The
migration was compiler-guided: only the sites rustc flagged as accessing the now-private
`Layer` field were rewritten, in five waves with the tree compiling between each, so
`LayerMask` accesses could not be touched by accident.

Two sites needed judgement rather than substitution: three rasterizer calls had to hoist
`blend_mode` out of the mutable borrow of the pixel buffer (a method call borrows the whole
layer where a field borrow did not), and the compositor now binds the source slice once per
layer rather than resolving it per pixel.

## Why

This is step one of a longer plan. Layer pixels are the data structure almost everything
touches — the rasterizer, 20 filters, 13 blend modes, transforms, history, export and the
project format. Changing the representation is a large, risky migration; removing callers'
dependence on the field is not. Nothing about the storage is promised to callers any more,
so a future change (higher bit depth, a different buffer kind) can be contained inside
`layer.rs` instead of being a repo-wide edit.

It does **not** introduce a new storage abstraction, a pixel-format enum, or 16-bit
storage. Deciding what such an abstraction must do is a design question that deserves its
own pass before it is implemented.

## Verification

| Gate | Result |
| :--- | :--- |
| Test suite | 80 tests, 0 failed |
| Compositing oracle | 702 combinations, byte-identical |
| Clipping corners | 234 combinations (short buffer, size ≠ canvas, non-indexable base) |
| Parallel vs serial | byte-identical, on a fixture asserted to take the parallel path |
| Determinism | repeated composites produce identical bytes |
| **AUR v1 compatibility** | **now tested** — a v1 byte stream loads with pixels, name, opacity and offsets intact (previously implemented but never exercised) |
| Corrupt project files | truncation inside artwork rejected; a lost preview thumbnail is tolerated on purpose |

The v1 test builds its fixture from the current writer by stripping the mask section AUR
v2 added and rewinding the magic, rather than transcribing a remembered layout — the test
cannot pass against a byte stream that never existed.

## Clippy

`cargo clippy -p aurelia-core --all-targets` reports **27 warnings before and after this
change, with an identical set of lint rules** - verified by running the same command on the
parent commit in a separate worktree and diffing the rule names, not just the count. They
are pre-existing style lints: too-many-arguments, loops whose index is only used to index
another slice, manual `is_multiple_of`, redundant `u8` casts in test fixtures.

Workspace-wide the total is 105, none of which reference the new accessors.

## Performance baseline

This release makes no performance claim. The numbers below exist so a future change has
something to be compared against: medians of five interleaved rounds, plus the best round
to show the spread, on a machine that is *not* quiet (it was running a desktop with a
browser open). Treat them as a relative reference, not an absolute target.

| Case | Median | Best round |
| :--- | ---: | ---: |
| Plain stack | 141.6 MPix/s | 156.1 |
| With layer mask | 127.2 MPix/s | 127.9 |
| General, opaque | 79.8 MPix/s | 83.6 |
| General, 50% coverage | 95.9 MPix/s | 112.0 |
| General, 10% coverage | 157.3 MPix/s | 173.6 |
| General, 10% + mask | 154.9 MPix/s | 159.2 |
| General, clipping | 56.6 MPix/s | 57.6 |
| General, clipping 10% | 137.1 MPix/s | 183.6 |
| All 13 blend modes | 64.3 - 79.9 MPix/s | up to 86.5 |

1920x1080, 4 layers, 20 iterations x 5 interleaved rounds. These are the medians of
rounds, so the spread between median and best (for example 137 to 184 on the sparse
clipping case) is the machine's noise, not the code's.

## Known

The installer is not Authenticode-signed; 4 of 75 engines flag it, which is disclosed in
the VirusTotal summary and why the pipeline runs with `--max-detections 4`. See the open
"Authenticode certificate" issue.

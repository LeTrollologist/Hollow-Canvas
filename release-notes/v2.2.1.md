# Aurelia v2.2.1

VirusTotal scanning is back in the release pipeline, now as its own stage that scans both
shipped binaries and blocks the release on detections.

## What's new

### `virustotal` stage (API v3)

A new stage sits between `package` and `verify`, so verdicts land in the release notes and in
`SHA256SUMS.txt` before anything is tagged:

- Scans **both** deliverables — `Aurelia-v2.2.1-win64.zip` **and** `Aurelia-Setup-2.2.1.exe`.
- Reuses an existing report when VirusTotal already has the hash, requests a re-analysis when
  the record exists but was never analysed, and only uploads genuinely new bytes.
- Polls `GET /analyses/{id}` until `status == completed` **and** engines actually reported, so a
  queued analysis can no longer masquerade as "0 detections" (the bug that shipped in 1.0.3).
- Writes `virustotal-summary.txt` (hashed and uploaded) plus `audit/virustotal-*.json`, and
  appends a verdict table to the release notes.
- **Refuses to publish** when any engine reports malicious/suspicious activity; `--force`
  overrides deliberately.

### Credential handling

The API key is read from **`VIRUSTOTAL_API_KEY` in the environment only** — the pipeline no
longer parses `.env`, and no key is ever written to the repository:

```powershell
$env:VIRUSTOTAL_API_KEY = "<your key>"
python scripts/pipeline.py v2.2.1
```

Without the variable the stage stops with instructions; `--skip virustotal` ships without a scan.

### Quota discipline

The public API allows **4 requests/minute and 500/day** (daily reset 00:00 UTC), which is why
`scripts/virustotal.py` paces every call 15 s apart, retries documented `429` / `503` / `504`
responses, and treats a `404 NotFoundError` while polling as "not visible yet". A two-artifact
scan uses roughly 6–12 requests.

### Pipeline plumbing

- Stage order is now `preflight → version → build → test → package → virustotal → verify →
  publish → ship`; `--from`/`--skip` accept `virustotal` like any other stage.
- New `make scan` target runs just the scan for the packaged artifacts.
- The release record (`releases/v2.2.1.json`) gains a `virustotal` block with per-artifact
  stats, engine counts and permalinks.

### Known VirusTotal results for this release

The portable zip reports **0 detections / 75 engines**. The installer is flagged by four
engines — Skyhigh (BehavesLike.Win32.ObfuscatedPoly.wc), DeepInstinct (MALICIOUS),
Cylance (Unsafe) and APEX (Malicious) — all generic ML/heuristic verdicts that name no
malware family. That is the well-known false-positive pattern for a freshly built, unsigned,
lzma2/ultra64 Inno Setup package: the payload it wraps (urelia.exe) is itself clean, and
the portable zip built from the same binary scans 0/75.

This release was therefore cut with --max-detections 4. The gate's default stays at **0**,
so any future build that trips more than its tolerated count still fails the pipeline.
Authenticode code signing is the real fix and is tracked in ROADMAP.md.

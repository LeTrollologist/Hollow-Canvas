# Aurelia v2.7.0

The compositor's general path gets faster for free — by changing how the code is arranged,
not what it computes.

## The number

| Workload (1920×1080, 4 layers) | v2.6.1 | v2.7.0 | |
| :--- | ---: | ---: | ---: |
| **General (offset + blend), opaque** | 79.8 MPix/s | **91.3 MPix/s** | **+14%** |
| General, 50% coverage | 95.9 MPix/s | 122.1 MPix/s | +27% |
| General, 10% coverage | 157.3 MPix/s | 191.9 MPix/s | +22% |
| General, 10% + layer mask | 154.9 MPix/s | 177.7 MPix/s | +15% |
| General, clipping layer | 56.6 MPix/s | 68.3 MPix/s | +21% |
| General, clipping at 10% coverage | 137.1 MPix/s | 215.1 MPix/s | +57% |
| **All 13 blend modes** | 64.3 – 79.9 MPix/s | **80.9 – 94.1 MPix/s** | every mode up |

Medians of five interleaved rounds; the harness prints the CPU, core count and compiler
with the numbers. Plain and masked compositing are unchanged in code and unchanged within
noise in measurement (141.6 → 133.4 and 127.2 → 129.0 against a machine that varies by
10–30%).

## What changed

The blend maths used to exist inside a function that took 8-bit pixels. It now exists
**once**, in working precision (`BlendMode::composite_working`), and the 8-bit entry point
is a thin storage wrapper over it. The compositor's general path runs a single generic loop
instantiated for `u8`, with the blend mode resolved once per layer instead of once per
pixel.

Nothing about colour, blending, alpha, clipping, masks or offsets changed. This is a
restructuring that happens to be faster, and the reason it is faster is that the compiler
can now see a single straight-line body per mode instead of a conversion-heavy one.

- **The 8-bit integer fast path is untouched** — the faster path for ordinary layers is
  exactly as it was.
- **No behaviour change:** the 702-combination oracle across all 13 blend modes is
  byte-identical, as are the clipping corners, parallel-vs-serial and determinism tests.
  81 workspace tests pass.

## Why it matters beyond the speed

This is step 2 of the pixel-format plan in `docs/pixel-format-proposal.md`. It was approved
on its own merits — the measurement in that plan showed the generic model beating the old
general path *before* any decision about higher bit depth. Today's release is that win,
taken early and independently:

- the storage abstraction (`LayerBuffer`) does not exist yet,
- the project format is unchanged (AUR v2),
- no filter or rasterizer was migrated,
- and 16-bit storage remains unimplemented.

## Known

The installer is still not Authenticode-signed; 4 of 75 engines flag it, which is disclosed
in the VirusTotal summary and why the pipeline runs with `--max-detections 4`.

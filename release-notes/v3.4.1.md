# Aurelia v3.4.1 — viewport / Navigator hotfix

A small patch release for the viewport feedback loop. No project-format or document-model
changes.

## Fixed

- **The Navigator now follows the brush live.** Previously the thumbnail keyed only on history
  generation, and a stroke is committed on mouse-up, so the Navigator did not move while
  painting.
- **The Navigator updates on paper changes.** Changing the canvas Background, toggling
  Transparent canvas, painting, filters, undo and redo now invalidate the thumbnail; a stale
  white thumbnail beside a changed viewport was the visible symptom.
- **Regression coverage for the canvas paper.** Empty 8-bit and 16-bit documents are tested to
  render white paper, so a blank viewport is not mistaken for a compositor failure.
- **Release verification accepts a published release.** `verify` no longer rejects a correct
  post-publication state when re-checking the draft operation.

## Viewport notes

The viewport is still an 8-bit presentation. This release does **not** add a custom GUI or a
16-bit display path; the Navigator fix is independent of that design question. A black canvas
is still a valid black paper value or opaque layer, not a display limitation.

The bilinear transparent-edge behaviour remains the documented known limitation from v3.4.0.

## Compatibility

- AUR v3 files, including 16-bit layers, open and save unchanged.
- 8-bit output and the transform digest gates are unchanged.
- 32-bit floating-point / linear-light editing is not part of this release.
